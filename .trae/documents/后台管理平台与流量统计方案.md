# 后台管理平台 + 流量统计（GA4）实施方案

## Context（背景与目标）

当前站点是一个纯静态 SSG 的 Next.js 15 外贸官网（45 页预渲染，SEO/GEO 优化完善）。所有内容（6 品类、18 产品、4 文章、12 条 FAQ、公司信息）都硬编码在 `lib/*.ts` 静态文件里，没有数据库、认证或后端。

用户需要新增两项能力：
1. **流量来向统计** —— 接入 Google Analytics 4，看到访问来源/国家/转化。
2. **后台管理平台** —— 在线编辑产品、品类、文章、FAQ、公司信息（全量），用 Supabase 数据库 + Supabase Auth 邮箱密码登录。

核心约束：**不能破坏现有 SEO/GEO 能力**（静态 HTML 预渲染、JSON-LD、canonical、sitemap、llms.txt、AI 爬虫白名单都必须保留）。因此数据层从静态文件迁移到 Supabase 后，前台渲染模式从纯 SSG 改为 **ISR（增量静态再生成）**，编辑后按需重新生成，既保留静态 HTML 的 SEO 优势，又支持在线编辑即时生效。

---

## 架构决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 数据库 | Supabase（Postgres）免费档 | 用户指定；自带 Auth、REST/JS SDK、Row Level Security |
| 认证 | Supabase Auth（email/password，关闭邮箱确认） | 用户指定；正规、可多人、支持重置密码 |
| 前台渲染 | ISR + on-demand revalidation | 保留静态 HTML 的 SEO 优势，编辑后 `revalidateTag` 即时刷新 |
| 数据访问 | `@supabase/supabase-js` + `@supabase/ssr` | 官方推荐，cookie 会话管理 |
| GA4 | `@next/third-parties/google` 的 `GoogleAnalytics` | 官方组件，自动处理加载 |
| 复杂字段存储 | JSONB 列 | 简化 schema 与后台编辑，避免多张关联表 |

## 数据库 Schema（Supabase SQL）

用 JSONB 存数组/嵌套结构，减少表数量：

```sql
create table categories (
  id uuid primary key default gen_random_uuid(),
  slug text unique not null,
  name text, nav_name text, tagline text, summary text,
  intro jsonb, image text, image_alt text,
  highlights jsonb, applications jsonb, faqs jsonb,
  sort_order int default 0,
  created_at timestamptz default now(), updated_at timestamptz default now()
);

create table products (
  id uuid primary key default gen_random_uuid(),
  slug text unique not null, name text, code text,
  category_slug text references categories(slug),
  summary text, description jsonb,
  composition text, weight_gsm int, width_cm int, weave text, finish text, shrinkage text,
  moq_meters int, stock_meters int, lead_time_min int, lead_time_max int,
  price_from numeric, price_to numeric, colors int,
  certifications jsonb, applications jsonb, features jsonb,
  image text, image_alt text, featured bool default false, faqs jsonb,
  sort_order int default 0,
  created_at timestamptz default now(), updated_at timestamptz default now()
);

create table articles (
  id uuid primary key default gen_random_uuid(),
  slug text unique not null, title text, description text, excerpt text,
  date date, updated date, author text, reading_minutes int, topic text,
  image text, image_alt text,
  key_takeaways jsonb, sections jsonb, faqs jsonb, related_categories jsonb,
  sort_order int default 0,
  created_at timestamptz default now(), updated_at timestamptz default now()
);

create table faqs (
  id uuid primary key default gen_random_uuid(),
  question text, answer text, sort_order int default 0,
  created_at timestamptz default now(), updated_at timestamptz default now()
);

create table site_settings (
  key text primary key,
  value jsonb not null,
  updated_at timestamptz default now()
);
```

启用 RLS：所有表开启 Row Level Security，公开读策略 + 仅认证管理员可写。

## 数据访问层（新增 `lib/` 文件）

- **`lib/types.ts`** —— 把 `Product`/`Category`/`Article`/`ArticleSection`/`Faq` 类型从 `lib/products.ts`、`lib/articles.ts` 抽出来统一存放（类型不变，仅移动）。`site` 对象新增 `Site` 接口类型。
- **`lib/supabase/server.ts`** —— Server 端 Supabase client（用 `cookies()`）。
- **`lib/supabase/client.ts`** —— 浏览器端 client（`createBrowserClient`）。
- **`lib/supabase/middleware.ts`** —— 会话刷新逻辑。
- **`lib/queries.ts`** —— async 数据访问函数，替代现有同步函数，全部带 `next: { tags: [...] }` 供 revalidation：
  - `getCategories()`、`getCategory(slug)`、`getProducts()`、`getProduct(slug)`、`getProductsByCategory(slug)`、`getFeaturedProducts()`、`getRelatedProducts(slug)`
  - `getArticles()`、`getArticle(slug)`、`getRecentArticles()`
  - `getFaqs()`、`getSite()`

**现有同步函数的处置**（`lib/products.ts`、`lib/articles.ts` 里的 `getProduct`/`getCategory`/`productsByCategory`/`featuredProducts`/`relatedProducts`/`getArticle`/`recentArticles`）：被 `lib/queries.ts` 的 async 版本取代后删除；纯工具函数 `productPriceRange` 保留（迁到 `lib/types.ts` 或留在新文件）。

## 前台页面改造（保持 SEO 输出不变）

**模式**（重复应用于约 20 个文件，此处描述一次 + 列代表性路径）：
把 `import { categories, products } from "@/lib/products"` 这类**静态数组顶层 import**，改为在组件内 `const products = await getProducts()`；组件由同步改为 `async function`。渲染 JSX、JSON-LD、canonical 输出**完全不变**，仅数据来源变了。

关键文件：
- 三个动态路由页 —— `app/products/[slug]/page.tsx`、`app/fabrics/[category]/page.tsx`、`app/insights/[slug]/page.tsx`：
  - `generateStaticParams` 改为 `async`（从 DB 查 slug）
  - `dynamicParams` 由 `false` 改为 `true`（允许后台新增的内容动态生成）
  - 页面组件 `await` 查询
- `app/page.tsx`、`app/fabrics/page.tsx`、`app/faq/page.tsx`、`app/insights/page.tsx`、`app/not-found.tsx`：数组 import → async 查询。
- `components/site-footer.tsx`、`components/product-card.tsx`、`components/rfq-form.tsx`：`categories` import → 传入 props 或改用 async server 数据。
  - 注意：`rfq-form.tsx` 是客户端组件，不能直接查 DB —— 改为由父页面（server）查好 `categories` 作为 props 传入。
- `app/sitemap.ts`、`app/llms.txt/route.ts`：改为 `async`，从 DB 读数据（sitemap 用 `await getProducts()` 等）。

**site 进 DB（全量）**：
- `lib/site.ts` 保留为 `defaultSite`（默认值 + `Site` 类型 + `absoluteUrl`/`whatsappLink` 纯函数）。
- 新增 `getSite()`：从 `site_settings` 读 `key='site'` 的 JSON，合并到 `defaultSite`（DB 值优先，缺失字段用默认）。
- 所有 `import { site } from "@/lib/site"` 的地方改为组件内 `const site = await getSite()`。
- `lib/schema.ts` 顶层 `orgId`/`siteId` 常量改为函数内计算（或 schema 函数改为接收 `site` 参数）；`lib/seo.ts` 的 `defaultOgImage` 不受影响。
- `app/layout.tsx`：`export const metadata` 改为 `export async function generateMetadata()`；`RootLayout` 改为 async，`const site = await getSite()` 后传入 JSON-LD。

## 认证 + 路由保护

- 根目录新增 `middleware.ts`：用 `@supabase/ssr` 刷新会话；除 `/admin/login` 外，所有 `/admin/*` 未登录时重定向到 `/admin/login`。
- `app/admin/login/page.tsx`：邮箱 + 密码登录表单（Supabase `signInWithPassword`）。
- 管理员账号：迁移脚本用 Supabase Auth Admin API（`service_role` key）创建 1 个管理员账号，密码由环境变量 `ADMIN_EMAIL`/`ADMIN_PASSWORD` 提供；关闭邮箱自动确认。

## 后台 UI（`app/admin/`）

- `app/admin/layout.tsx`：侧边栏布局（Dashboard / Products / Categories / Articles / FAQs / Settings / 退出登录），未登录跳转登录页。
- `app/admin/page.tsx`：仪表盘 —— 统计卡片（产品/品类/文章/FAQ 数量、最近更新）+ **流量统计入口**（GA4 报告链接，GA4 数据本身上 Google Analytics 后台查看，不在站内自建图表）。
- `app/admin/products/page.tsx` + `app/admin/products/[id]/page.tsx`：产品列表 + 新建/编辑表单。
- `app/admin/categories/page.tsx`：品类列表 + 编辑。
- `app/admin/articles/page.tsx` + 编辑页：文章列表 + 编辑（`sections`/`faqs` 复杂结构用分块表单或 JSON 编辑区）。
- `app/admin/faqs/page.tsx`：FAQ 列表 + 编辑（含排序）。
- `app/admin/settings/page.tsx`：公司信息表单（name/legalName/email/phone/whatsapp/address/social/certifications/description）。

**CRUD 全部通过 Server Actions**（`app/admin/actions.ts` 或各资源目录下）：写入 Supabase 后调用 `revalidateTag('products'|'categories'|'articles'|'faqs'|'site')` + `revalidatePath(相关路径)` 触发前台 ISR 刷新。

## GA4 接入

- `app/layout.tsx` 的 `<body>` 内加 `<GoogleAnalytics gaId={process.env.NEXT_PUBLIC_GA_ID!} />`（来自 `@next/third-parties/google`）。
- 环境变量：`NEXT_PUBLIC_GA_ID=G-XXXXXXXXXX`。

## 数据迁移脚本

- `scripts/seed.mjs`（或 `.ts`）：读取现有静态数据（`lib/products.ts` 的 `categories`/`products`、`lib/articles.ts` 的 `articles`、`lib/faqs.ts` 的 `faqs`、`lib/site.ts` 的 `site`），用 `service_role` key 写入 Supabase 对应表。
- 幂等：可重复执行，按 slug/key upsert。

## 分阶段实施（每阶段可独立验证）

1. **GA4 接入** —— 加依赖 + layout 组件 + env。验证：构建通过，页头出现 gtag 请求。
2. **Supabase 基础 + schema + seed** —— 建表 SQL、数据访问 client、seed 脚本跑通现有数据入库。验证：Supabase 表里能看到 6/18/4/12 条数据。
3. **前台数据层 async 化 + ISR** —— `lib/queries.ts` + 所有前台页面/组件改 async 查询，`generateStaticParams` async、`dynamicParams=true`、revalidate。验证：`npm run build` 通过，页面视觉与 SEO 输出（JSON-LD/canonical/sitemap/llms.txt）与改造前一致。
4. **认证 + 中间件 + admin 骨架** —— middleware 保护、登录页、admin 布局、seed 管理员。验证：未登录访问 `/admin` 被重定向，登录成功进入后台。
5. **后台 CRUD 界面** —— 产品/品类/文章/FAQ/设置的增删改查 Server Actions + 表单。验证：后台改一个产品价格，前台对应页刷新后即时更新。
6. **端到端验证** —— 全量回归（构建、45 页、SEO 输出、后台 CRUD、GA4、登录登出）。
